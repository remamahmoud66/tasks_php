# مشروع OOP CRUD بعد تحويله إلى API

## فكرة المشروع
المشروع يستخدم `DB_con` في `db.php` للاتصال بقاعدة البيانات وتنفيذ عمليات CRUD. ملفات PHP داخل `api/` تستقبل طلبات HTTP وتعيد JSON، وواجهة HTML تستخدم JavaScript و`fetch()` لقراءة البيانات وإضافتها وتعديلها وحذفها.

## تشغيل المشروع على XAMPP
1. فك ضغط `OOP_CRUD_API.zip`.
2. انسخ مجلد `OOP_CRUD_API` إلى `C:\xampp\htdocs\`.
3. شغّل Apache وMySQL من XAMPP.
4. افتح phpMyAdmin، وأنشئ قاعدة بيانات باسم `register_task` إذا لم تكن موجودة.
5. اختر قاعدة `register_task` وشغّل `database.sql`. أو إذا كانت الجداول موجودة أصلًا، لا تحذفها ولا تعِد إنشاءها؛ تأكد فقط أن الأعمدة المطلوبة موجودة.
6. افتح `db.php` وتأكد من `DB_HOST`, `DB_USER`, `DB_PASS`, `DB_NAME`, و`DB_PORT`. الإعداد الحالي للمنفذ هو `3307`. إذا كان MySQL عندك يعمل على `3306` غيّره إلى `3306`.
7. إذا كان جدول `products` قديمًا ولا يحتوي عمود `image`، نفّذ أمر `ALTER TABLE` المعلّق في `database.sql` مرة واحدة فقط.
8. افتح: `http://localhost/OOP_CRUD_API/`.

**مهم:** لا تفتح ملفات HTML بالنقر المزدوج، لأن `fetch()` يحتاج أن تعمل الصفحات من خلال Apache/PHP. ولا تشغّل `database.sql` على قاعدة فيها بيانات مهمة قبل التأكد من اسم القاعدة؛ الأوامر لا تحذف البيانات، لكنها تنشئ الجداول الناقصة.

## صفحات الواجهة
- `index.html`: الصفحة الرئيسية وروابط الأقسام.
- `users.html`: عرض المستخدمين وإضافتهم وتعديلهم وحذفهم.
- `categories.html`: عرض التصنيفات وإضافتها وتعديلها وحذفها.
- `products.html`: عرض المنتجات وإضافتها وتعديلها وحذفها، مع رفع صورة اختيارية.

كل صفحة من هذه الصفحات تجمع نموذج الإضافة/التعديل وجدول السجلات في نفس الصفحة. أزرار Edit تعبئ النموذج بالسجل المختار، وDelete تطلب التأكيد قبل الحذف.

## ملفات مهمة
- `db.php`: كلاس `DB_con` واتصال PDO ودوال التعامل مع الجداول.
- `api/common.php`: أدوات مشتركة لإرجاع JSON، وقراءة الطلبات، والتحقق من المعرّفات ورفع الصور.
- `api/users.php`: API للمستخدمين.
- `api/categories.php`: API للتصنيفات.
- `api/products.php`: API للمنتجات.
- `assets/js/api.js`: دالة `apiRequest()` المشتركة التي ترسل الطلب وتقرأ JSON، ودوال عرض الرسائل وحماية النصوص عند عرضها.
- `assets/js/users.js`, `categories.js`, `products.js`: منطق الواجهة لكل قسم.
- `assets/css/style.css`: تنسيق الصفحات.
- `uploads/`: الصور التي يتم رفعها للمنتجات.

## كيف تسير عملية قراءة البيانات؟
1. تفتح مثلًا `products.html`.
2. ينفذ `products.js` الدالة `apiRequest('products.php')`.
3. ترسل `api.js` طلب `GET` إلى `api/products.php`.
4. يستدعي endpoint دالة مثل `$db->fetchProducts()` من `db.php`.
5. ترجع دالة قاعدة البيانات مصفوفة من السجلات.
6. يحول endpoint النتيجة إلى JSON ويرسلها للواجهة.
7. يقرأ JavaScript الاستجابة عبر `response.json()` ويعرض السجلات داخل الجدول.

## مسارات الـ API
كل المسارات أدناه نسبية إلى مجلد `api/`:

| المسار | HTTP method | الوظيفة |
|---|---|---|
| `users.php` | GET | قراءة كل المستخدمين |
| `users.php?id=1` | GET | قراءة مستخدم محدد |
| `users.php` | POST | إضافة مستخدم |
| `users.php` | PUT | تعديل مستخدم بإرسال JSON يحتوي `id` |
| `users.php?id=1` | DELETE | حذف مستخدم |
| `categories.php` | GET / GET مع `id` | قراءة التصنيفات أو تصنيف محدد |
| `categories.php` | POST | إضافة تصنيف |
| `categories.php` | PUT | تعديل تصنيف بإرسال JSON يحتوي `id` |
| `categories.php?id=1` | DELETE | حذف تصنيف |
| `products.php` | GET / GET مع `id` | قراءة المنتجات أو منتج محدد |
| `products.php` | POST | إضافة منتج، أو تعديله إذا أُرسل `id`؛ يستخدم `FormData` لدعم رفع الصور |
| `products.php?id=1` | DELETE | حذف منتج |

استجابة ناجحة نموذجية:

```json
{"success":true,"data":[{"id":1,"name":"Example"}]}
```

استجابة خطأ نموذجية:

```json
{"success":false,"message":"A helpful error message"}
```

## ملاحظات مهمة
- لا تُرسل كلمة مرور المستخدم ضمن استجابات `GET`.
- كلمات المرور الجديدة تُخزّن باستخدام `password_hash()`.
- إذا كان النظام القديم يعتمد على كلمات مرور مخزنة كنص عادي، فإن هذا المشروع لا يحوّل كلمات المرور القديمة تلقائيًا. إذا كان هناك تسجيل دخول آخر يستخدم الجدول نفسه، راجعي طريقة التحقق من كلمة المرور قبل دمج النظامين.
- لا يمكن حذف تصنيف مرتبط بمنتجات؛ ستظهر رسالة توضح ضرورة حذف المنتجات أو نقلها إلى تصنيف آخر أولًا.
- صور المنتجات المسموحة JPEG/PNG/GIF/WEBP، والحد الأقصى 2 MB.
- هذا مشروع تدريبي محلي؛ لا تنشريه على الإنترنت كما هو، لأن endpoints لا تحتوي على تسجيل دخول أو صلاحيات.
- إعدادات الاتصال الحالية مأخوذة من المشروع الأصلي: `register_task` والمنفذ `3307`. عدّليها إذا كانت بيئتك مختلفة.
